## 阶段 1：容器基座
**Dockerfile（多阶段）**，版本固定：
- `base`：`debian:bookworm-slim` + git/curl/ripgrep/p7zip-full/ffmpeg/jq/cmake/ninja/build-essential/unzip/python3(venv)/Node 22（≥22.18）。cmake/ninja/build-essential 保留在镜像中（thtk 临时编译也依赖它们）。
- `tools`：
  - emsdk（仓库当前用 Emscripten 6.0.9，固定该版本，不可用则取最新稳定并记录偏差）
  - wasi-sdk x86_64-linux（参考 34.0，取最近可用 release）→ `/opt/wasi-sdk`
  - Temurin JDK 21 + **Ghidra 12.1.3**（与参考工作流导出器 API 一致）→ `/opt/ghidra`，`analyzeHeadless` 进 PATH
  - Python venv：unicorn、capstone、pillow、numpy
- `dev`：非 root 用户（--build-arg UID/GID 匹配宿主，rootless podman），WORKDIR `/work`。
- `ci`：精简目标（node/python/emsdk/wasi-sdk + 测试依赖，无 Ghidra）。

**Makefile**：`make image` / `make image-ci` / `make shell` / `make exec CMD=...` / `make thtk`（临时克隆编译）/ `make thtk-clean`。

## 阶段 2：原版清点与资源提取（容器内）
1. `make extract`：解包 `th13ogg.7z` → `games/th13/`；SHA256 清单 + EXE 版本判定（1.00a/b/c）。**首要步骤**——压缩包内容未验证，若缺 `th13.exe`/`th13.dat` 立即停止上报。
2. `make thtk` 临时构建 thtk → 提取：`thdat -x 13` → `reference/raw/`；`thecl`/`thanm`/`thstd`/`thmsg` dump → `ports/th13/web/reference/dumps/`；贴图/OGG BGM 对齐 launcher 期望的 `th13.data + bgm-ogg/` 结构（模仿 th10 写 `prepare-th13-content.mjs`）→ 提取完成、校验 dump 完整后 `make thtk-clean`。
3. 记录 th13 实际格式版本（ECL/ANM 代数）到 `docs/ASSETS.md`。
4. 原版资产与提取大产物全部 gitignore（仓库红线：不携带任何原版文件）。
