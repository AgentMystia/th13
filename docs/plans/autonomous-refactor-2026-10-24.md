# th13 可接手架构：无需历史会话的确定性开发

状态：用户于 2026-10-24 批准；本文规定架构和验收范围，不是完成报告。当前完成状态只能来自 `scripts/verify.py resume` 及匹配当前输入的运行证据。

## 1. 目标与不可替代的证明

将 v1.00c 原版迁至 eagler-touhou，保留 th15 共享 GLES 后端、ZunGraphics 语义边界、AnmManager 句柄生命周期。主 Agent 也可能是弱模型，故任务选择、前置资格、验证、停止及交接必须可执行，不能依赖会话记忆或“强模型裁决”。

验收分层：

1. 原版世界资格：版本、资产、初值、种子、输入及采样相位正确。
2. 捕获完整性：请求窗口完整，帧唯一连续，事件流另有生产端完成记录，无崩溃或吞报。
3. 行为与完整渲染语义一致：真实提交及有效资源内容逐字段比较。
4. 后端数值与最终游戏画布一致：独立原版 framebuffer 真值与实际浏览器输出自动比较；无须人眼，不用相似度阈值冒充相等。
5. 声明范围内所有必需场景覆盖：缺项不自动通过。

同一后端绘制两份相同命令，只证明该后端的自一致；假设备清单相同不能独立认证光栅、字体、纹理更新或最终呈现。没有独立原版输出环境时，第4层保持 BLOCKED。有限输入/配置认证不等于对任意输入、驱动及 GPU 的数学证明。

## 2. 结构决定

### 2.1 验证与状态

外层 `verification/` 定义策略、任务及 schema；`scripts/verify.py` 是唯一接手/验收入口。运行证据位于 ignored `artifacts/verification/`。内层产品接口文档留在 `ports/th13/docs/`；任务卡只引用，不复制。

任务状态：PENDING → READY → ACTIVE → VERIFYING → DONE；失败出口 FAILED、BLOCKED、STALE。只允许程序根据证据决定完成；状态 JSON 不是可手工编辑的待办清单。任务关联源码、dirty 内容、工具链、契约、输入及产物摘要。相关依赖变化使证据失效；报告自身变化不应导致无限重验。

常规施工不能改策略、golden、阈值或测试来迎合实现。验证器维护任务必须单列范围和负控；这些是防误操作措施，不是针对拥有同等写权限的恶意代理的安全沙箱。

### 2.2 生产绘制的单一真值

目标路径：场景/ANM → ZunGraphics → 本作真实提交边界 → 共享 Renderer。

trace 在同一边界只读观察有效 State、几何和资源版本。不存在单独的“模拟原版设备状态”真值。即时同步消费允许避免整帧几何复制；延迟消费必须拥有字节及资源版本，不能保留悬空 VM/顶点指针。

新契约逐步覆盖：完整顶点/索引、primitive 数、layout、矩阵、viewport、target、depth、blend、alpha、fog、cull、mask、sampler、combiner、纹理内容及版本、upload/copy/clear、present/commit 边界。尚未实现的能力显式 unqualified；unknown 不能转成合法 null。

旧 DrawCapture v1/harness 窗保留作 legacy 诊断，不认证生产全链路。捕获专用标题 `@R` 补画不准进入新生产证据；真实合成未实现则任务保持失败，不删除原版提交、不往网页画白条冒充修复。

### 2.3 场景驱动与共享基座

全链路验证最终运行生产 Application/SceneDisplay/FrameScheduler 的同一 tick，平台服务注入输入、时间、存储、音频和提交消费者。不得继续新增手工镜像游戏流程的主 harness。

借用 th15 的 StageDrawFrame、StageVisibility、ScreenCompositor、SceneCapture 职责，不套用其本作常量。StageScenery 的模拟、可见性、几何准备和提交分离；若原版 draw 必须写回，则显式每逻辑帧执行一次。高刷显示不能再次模拟游戏。

共享 `portable/sdl` 文件保持与 th15 一致。本作差异放在配置/调用层；必要分叉必须有原版证据、上游候选及独立授权。捕获重构不得改掉整体 glBufferData 上传模式。

## 3. 执行阶段及解锁条件

| 阶段 | 交付 | 解锁条件 |
|---|---|---|
| 接手基础 | 简短 AGENTS、runner、状态机、任务卡、负控、证据与交接 | 固定工具自测和失败路径通过 |
| 提交基础 | 生产与 trace 共用入口，完整几何及状态观察 | 捕获开/关不改生产输出、旁路受检、错误传播 |
| Replay 资格研究 | 初值/输入消费点与最小实验方案 | 具名证据，未知字段保留 raw；研究完成不等于资格认证 |
| Replay 资格认证 | 同初值/输入、双跑、关卡里程碑 | 正确场景且原版 Replay 路径证据闭合 |
| 完整捕获 | 真实 STD、纹理/字体内容、设备状态和 RT 依赖 | 每类新增字段的变异负控能检出差异 |
| 生产驱动统一 | 浏览器/无头共享场景编排 | 无平行场景模拟真值，生产浏览器门禁 |
| 模块还原 | 玩家/射击/伤害/掉落/计分/HUD/STD/菜单/对话/暂停/结算 | 模块原版证据、负控、单测和主线窗 |
| 后端认证 | 独立 GPU fixtures、提交降低保持性、自动 framebuffer 对照 | 独立原版输出可用；实际浏览器展示验证 |
| 全游戏覆盖 | 按资产及可达分支扩展角色、机体、难度、关卡和画面 | 首条菜单→Stage1→Stage2 主线通过不代替全游戏完成 |

下一阶段尚无事实时只登记有明确产物的研究任务，不编造实现细节。不能用“架构待定”无限探索，也不能用“无人能回答”绕过真正的资格阻塞。

## 4. 有限施工循环

每张任务卡必须说明目标/非目标、依赖、必读文件与原版锚点、允许/禁止修改范围、正负控、固定命令、产物、最多三轮修订及停止条件。

失败分类固定：

- 环境/构建/路径：停止游戏调参，不消费旧产物。
- 原版资格：先修参考世界，不能调 port 拟合错误 oracle。
- 捕获/资源未知：先补观察能力，不能宣布一致。
- 已认证下的机制分歧：定位具名模块，不按绝对帧抄答案。
- 三轮无机制进展：保存最小复现，进入机制复核任务。
- 修改契约/共享架构/验收范围：形成证据决策请求并停止该分支；其他无依赖 READY 任务可继续。
- 提供方故障：保留运行，遵守恢复操作，不偷偷换账户或模型。

## 5. 工作流和跨会话接手

首先完成工具及提交基础；随后 `CreateWorkflow` 使用用户指定 CPA `zai-glm-5-3`（本宿主 ID `new-provider/zai-glm-5-3`）。接手演练不给历史会话总结，只给仓库入口；验收能否正确选择任务、拒绝伪绿并生成交接。

工作流执行固定容器命令决定通过；施工 Agent 不自报通过。任务文件不重叠才并行；独立复核关注机制证据、越权改动和测试专用行为，不重复整套验收。每任务最多三轮。

运行 id、脚本路径、当前任务和阻塞信息写入 ignored 交接证据。恢复用 ResumeWorkflowRun；修订用 Edit + AmendWorkflow，未变化的 ask 文本不改。不得把历史执行日志或整个会话作为下一模型的必读材料。

## 6. 本轮交付检查

必须真实执行工具负控、Python oracle 工具测试、Node 套件（含 ECL/UI/Replay 包装）、ANM、WASI/网页/捕获构建、浏览器统计、提交边界测试及历史 golden 全跑。记录每项失败及资格边界，不以“双构建绿”替代测试。

入口、策略、任务图和命令必须实际存在；接手演练发现需要口头补充时先修入口。没有完成的项目保持未认证，本设计文档本身不授予 DONE。
